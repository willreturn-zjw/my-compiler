# 全流程测试过程

## 1. 测试范围

`测试用例.md` 中的 46 条用例由 pytest 参数化执行：

- TC01–TC15：SysY 源码到 Koopa IR，以及 IR 构造和数据流分析相关行为；
- TC16–TC30：Koopa IR/前端生成结果到 ARMv8 汇编的静态生成行为。
- TC31–TC46：补充全流程结构断言、异常处理及命令行场景，详见下表。

本轮测试不执行 ARMv8 汇编。后端结果通过汇编文本检查验证，因此不要求本机具有 AArch64 汇编器、链接器或运行环境。

## 2. 执行前置条件

1. 在 Linux/WSL/AArch64 目标环境准备可执行的编译器程序，或者先按 README 的构建说明完成构建；
2. 确认编译器支持 `-S <input> -o <output>` 调用形式；
3. 使用 Python 3.9 或更高版本并安装 pytest；
4. 如果需要排查单条用例，启用 `--keep-artifacts` 保留中间文件。

## 3. 单条用例流程

每条参数化用例都按相同流程执行：

1. 创建唯一临时目录；
2. 写入该用例的 SysY 输入；
3. 在该目录中调用编译器，隔离项目固定生成的 `parse.kp`；
4. 检查编译器退出码和预期文件是否生成；
5. 前端用例检查 `parse.kp`，后端用例同时检查 `parse.kp` 和 `.s` 文件；
6. 使用用例的正则断言检查 IR 指令、ARMv8 指令、寄存器、标签、数据段和访存模式；
7. 记录状态、耗时和失败原因，然后删除临时目录，除非指定保留产物。

## 4. 状态判定

- `PASS`：编译器正常退出，预期文件存在，所有静态断言满足，禁止模式未出现；
- `FAIL`：编译器异常退出、超时、输出文件缺失或静态断言不满足；
- `BLOCKED`：当前环境无法运行指定编译器，例如缺少可执行文件、文件存在但其 ELF 解释器/动态库不可用，或目标架构不匹配。pytest 界面显示为 `SKIPPED`，汇总报告统一记为 `BLOCKED`。

`BLOCKED` 不等价于通过，也不等价于编译器缺陷。它表示需要补充构建或运行环境后重试。脚本仅在存在 `FAIL` 时返回退出码 1；存在 `BLOCKED` 时返回 0，并在报告中单独统计。

## 5. 结果产物

默认输出目录为 `test-results/`：

- `results.md`：面向人工评审的用例结果表；
- `results.csv`：便于 Excel 汇总和筛选；
- `results.json`：便于 CI 或其他程序读取；
- `artifacts/TCxx/`：仅在启用 `--keep-artifacts` 时生成，包含输入、`parse.kp`、汇编和诊断信息。

## 6. 测试完成标准

在目标构建环境中，46 条用例均应完成执行；不存在 `FAIL`；所有 `BLOCKED` 都有明确的环境原因并在补齐环境后复测。后端静态测试通过后，如需证明运行时语义，还应在具备 AArch64 环境时另行执行汇编、链接和运行测试。

## 7. 新增 TC31–TC46

在 Linux 项目根目录构建并运行：

```bash
bash build.sh
python3 -m pip install -r tests/requirements.txt
python3 -m pytest -q tests/test_compiler.py -m extended --compiler ./test/compiler --keep-artifacts
```

省略 `-m extended` 执行全部 46 条，使用 `-m baseline` 执行原有 30 条。`-k TC43` 可定位单条。`--report-dir test-results/extended` 可将新增结果单独保存。编译器须匹配 Linux 主机架构；仅生成汇编时无需 AArch64 主机。

| ID | 自动检查内容 |
|---|---|
| TC31 | AND/OR 分支的求值路径可到达 side、短路路径不可到达同一调用；逻辑非和归一化指令；汇编条件跳转 |
| TC32 | f32 函数签名、调用、浮点加法、整浮转换、浮点比较和返回寄存器 |
| TC33 | void 签名、无赋值调用、基本块终结、隐式 ret 和汇编调用 |
| TC34 | 内建声明类型、计时函数改写与行号参数、所有 IR/汇编调用及寄存器类型 |
| TC35 | 递归结果参与乘法、基本块终结、递归汇编调用、链接寄存器保存恢复 |
| TC36 | h→g→h→f 的调用顺序和 IR 实参来源、汇编调用顺序及保存恢复指令 |
| TC37 | 全局 g/gf/a 类型、零初始化、汇编零值和数据大小、常量 C 的折叠 |
| TC38 | 1024 元素数组、0/1023 下标、4092 字节末元素偏移、栈帧大小与对齐、无移位 add/sub 立即数范围 |
| TC39 | 18 个实参、两类 0–7 参数寄存器写入、两个溢出参数的独立 outgoing 栈槽 |
| TC40 | f32 返回签名、除法、浮点返回寄存器、调用者浮点比较和整数返回寄存器 |
| TC41 | 两层循环、continue/break 分别跳转内层入口/出口、跳转目标存在 |
| TC42 | 两分支写入同一变量、合流目标一致、合流后 load、汇编调用/读取/分支 |
| TC43 | 正常非零退出、语法诊断、无断言/信号崩溃、无有效 main IR 或非空汇编 |
| TC44 | 同一输入先无 -S 再带 -O2/-S；IR 内容、无汇编模式及指定输出 |
| TC45 | 含空格输入/输出路径作为完整参数传递、指定产物内容 |
| TC46 | 同工作目录顺序编译两个源，保存两次快照，第二次返回 2 且无 first 残留 |

扩展用例分别检查 IR 和汇编，避免汇编断言被 IR 文本满足。每个有检查的 IR 函数还验证基本块终结和跳转目标。TC43 的断言崩溃属于 FAIL，不会按“预期非零退出”误记通过。

启用 `--keep-artifacts` 后，成功或失败均复制产物至 `artifacts/TCxx/`，再清理临时目录。扩展执行器保存每次调用的 `*.diagnostics.json`（命令、退出码、stdout、stderr）、`*.sy`、`*.kp`、`*.s` 快照；超时保存 `*.timeout.txt`。尚未生成的文件不创建占位产物。

这是静态集成测试：TC36 的保存恢复检查不证明每个中间值运行时均不被覆盖，TC39 不直接证明被调用者读取栈参数的值，TC42 不直接检查内部支配/活跃集合。TC38 的地址检查识别当前后端使用的直线常量装载/add/lsl 序列，并非通用汇编解释器。若将来修改 IR 命名或汇编降低方式，应同步维护结构检查。

TC37 按 i32/f32 每元素 4 字节、TC38 按清单明确的 1023×4 偏移检查。当前后端源码存在按 8 字节存储标量/数组元素的实现，TC43 当前入口也存在语法失败断言；因此新增测试可能揭示已有实现缺陷，不预设所有新增用例都会通过。这里只新增测试，不修改编译器实现。
